# 常见问题

[文档首页](README.md) · [快速开始](quickstart.md) · [使用指南](user-guide.md)

先按“问题停在哪一步”定位：**页面访问 → 后台连接 → 收到消息 → 识别与审批 → 转存 → 整理**。不要一遇到问题就重建容器或清空数据；这可能丢失登录态、历史记录和转存检查点。

## 安装与访问

### 1. Docker 已启动，为什么另一台电脑打不开管理台？

默认端口是 `127.0.0.1:28080:28080`，只监听部署机器本机。

- 在 NAS 上部署，就不能把自己电脑浏览器里的 `127.0.0.1` 当成 NAS。
- 局域网访问需调整端口绑定，再用 NAS 的局域网 IP 打开，并检查防火墙。
- 公网服务器优先使用安全隧道或受控的反向代理，不建议直接开放管理端口。

具体操作见 [打开管理台](quickstart.md#打开管理台)。

### 2. 为什么用域名打不开首次设置，或者提示不能设置密码？

首次设置限制为本机或局域网，并且地址栏需要是 IP 或 localhost，目的是避免其他网页借域名访问劫持初始化。

先用局域网 IP 或安全隧道完成首次密码设置，再配置域名和 HTTPS。不要靠关闭鉴权来解决。

### 3. 管理台正常，为什么 Worker 显示 unhealthy？

`web` 与 `worker` 是两个进程。Web 健康只表示管理 API 能回答请求，不代表 Telegram 已连接或后台能转存。

依次检查：

1. 是否只启动了 `web`，还没有执行 `docker compose up -d`。
2. 是否填写 Telegram API ID / API Hash，并在终端完成个人账号登录。
3. 总览显示的是未登录、连接失败，还是 Worker 心跳离线。
4. `docker compose logs --tail=100 worker` 中的具体原因。

未完成 Telegram 配置或登录时，Worker 可以运行但健康检查不通过；补齐配置后通常会自动连接。

### 4. 数据目录出现 Permission denied 怎么办？

默认命名卷不需要额外授权。使用宿主机目录时，要确保 `web` 和 `worker` 看到同一份数据，并以有权限的用户运行；自定义 UID 时还需把 `HOME` 指向可写的数据目录。

按 [宿主机目录部署说明](deployment.md#用宿主机目录存放数据) 修正。不要把 `chmod -R 777` 当成通用解决办法，数据目录里有登录凭据。

## 消息与来源

### 5. 添加来源后，为什么没有收到旧消息？

新来源从加入后开始接收新消息，不自动导入之前的历史。已有来源断线后的补拉使用保存的接收进度，并受到条数和天数限制；两者不是同一种情况。

可以先用「测试识别」验证格式，但测试不会生成真实任务。

### 6. 频道发了新消息，Reelay 为什么没反应？

按顺序检查：

1. 登录的个人账号是否已经关注频道、加入群组或与 Bot 对话。
2. 来源是否保存成功，`@用户名` 或数字 ID 是否填写正确。
3. Worker 在线且 Telegram 已连接。
4. 去「任务」找记录：可能已经收到，只是被关键词、重复内容或订阅过滤忽略。
5. 查看任务轨迹；找不到记录时再查运行日志和监听状态。

控制 Bot 能收到你发的命令，不代表用于监听的个人账号已经登录成功。

### 7. Telegram 没有审批卡片，是不是处理失败？

不一定。可能是：

- 没配置控制 Bot、owner 数字 ID 不对，或还没向自己的 Bot 发过 `/start`。
- 来源关闭了 Bot 通知。
- 资源已自动放行或被忽略，不属于待审批。
- 这是断线补拉的历史消息，不逐条推送审批卡片。
- 通知发送暂时失败，在总览或日志中可查看。

先在管理台看任务状态。**重发通知只补发消息，不会重新转存文件。**

### 8. “测试识别”显示成功，为什么网盘没有文件？

测试只预览解析、置信度与决策，不创建任务、不转存。预览里的“会转存”是按当前条件推算的结果，不是完成通知。

实际转存需要来源的新消息进入正式任务流程，随后通过审批或自动放行、转存核验和整理。

## 识别、审批与订阅

### 9. 有电驴链接，为什么仍被忽略？

先看任务轨迹，而不是只看链接：

- “消息必须包含”只设置了 `115` 或 115 域名，会挡住电驴消息；需要允许 `ed2k://`。
- 其他关键词、类型、清晰度或订阅条件可能没有通过。
- 链接提取、是否符合收藏条件、115 能否云下载，是三件不同的事。

旧版测试界面可能把仅有电驴链接的结果误标为“没有找到 115 链接”；v1.5.0 起已修复。不要为了让徽标变绿而伪造 115 链接。

### 10. 为什么选了“AI 处理”，仍然进入待审批？

“AI 处理”不是无条件批准。低置信度、TMDB 匹配不可靠、AI 解析降级、过滤信息不明确或分享检查存在问题时，仍可能要求人工确认。

处理轨迹会记录原因。先解决缺失的信息或服务故障，不建议单纯降低置信度门槛来绕过检查。

### 11. 为什么选了“人工确认”，订阅的新集却自动转存了？

如果放行方式是「规则 + 订阅放行」或「AI 按偏好判断」，符合条件的订阅新集可能从人工确认提升为自动放行。

希望**每条都确认**时，使用「人工确认」+「规则判断」。各组合见 [选择处理方式](user-guide.md#选择适合你的处理方式)。

### 12. 已订阅，为什么仍然没有自动转存？

检查是不是同一部作品、同一季，以及 TMDB 是否匹配成功。还要确认来源支持订阅放行，资源置信度、过滤条件、分享信息等是否通过，是否已经全部入库。

仅把片名写进订阅表，不会绕过身份校验；季不明或跨多季时也不会由订阅强行放行。订阅新集自动处理的条件见 [追剧订阅](user-guide.md#追剧订阅与不再接收)。

### 13. 我只想收订阅，为什么未订阅作品仍出现在待审批？

「规则 + 订阅放行」只让订阅新集更容易自动通过，不会排除未订阅作品。

需要开启独立的「仅处理订阅」开关。该功能自 **v1.5.0** 起支持，早于 v1.5.0 的版本没有这个设置；可设置全局默认或来源覆盖，操作见 [使用指南](user-guide.md#仅处理订阅)。开启后无法匹配有效订阅的也会忽略，因此先确认 TMDB 和订阅配置正确。

### 14. 取消订阅后，为什么还有资源被处理，或还有缺集提醒？

取消订阅不会取消已经批准的任务，也不等于拉黑作品。

- 来源本身是自动处理且没开“仅处理订阅”时，之后的消息仍可能按普通规则转存。
- 开关和来源设置不自动重算旧任务。
- 缺集插件启用“自动跟踪”时，近期有更新的作品仍可能被跟踪。

彻底不再接收某部作品，应使用「不再接收」；只是不想收到缺集提醒，则使用对应提醒中的“不用等了 / 不再提醒”。

### 15. AI 生成识别规则报 invalid，是什么原因？

`invalid` 不一定是网络不通，也可能是模型返回了合法 JSON，但字段、类型或结构不符合要求，或者规则校验不通过。

v1.5.0 起补充了明确的输出结构要求，并兼容部分已知返回格式。仍失败时：

1. 查看页面具体错误和 AI 调用记录，区分格式问题、超时与权限问题。
2. 确认模型适合结构化输出；接口确实不支持 schema 时按 [配置参考](configuration.md#识别与决策defaults--sources) 调整响应格式。
3. 换更简单、有代表性的样例，必要时换模型或手写规则。

反复重试可能持续消耗 Token；生成成功也要试跑核对，不能直接视为正确。

### 16. 可以完全不调用 AI 吗？

来源可选「规则识别」与「规则判断」或「规则 + 订阅放行」，不依赖 AI 来解析和决定收藏。但如果仍配置了 AI，生成规则、自然语言助手、整理选集辅助或日报等功能可能使用它。

希望完全不调用 AI 时，不配置 AI 服务，并避免使用 AI 功能。TMDB、Telegram 和 115 则仍是各自独立的网络服务；“不用 AI”不等于整个项目离线运行。

## 115 转存与整理

### 17. 为什么消息写 1 集，实际转存了多集？

默认“集数依据”为分享：按分享中的实际文件，转存范围内未入库的集，而不是只相信消息文案。例如同一分享从第 1 集更新到第 8 集，本地记录缺多集时可能一起补齐。

只想处理消息声明的集，可把来源的集数依据改为“消息”，仍需通过分享文件校验。

### 18. 电驴链接是下载到 NAS 吗？115 分享失效后会自动改用电驴吗？

不是。电驴链接交给 115 云下载，文件目标仍是你的 115 网盘。能否完成取决于资源可用性和 115 的服务能力。

同一消息同时提取到 115 分享和电驴链接时，优先处理 115 分享；**不是先测试分享失效，再自动回退到电驴**。

### 19. 一直显示转存结果待核验，能不能再转一次？

不要把“还没核验到”当成“肯定没转存”。115 可能已接收请求，但文件还没全部落地。

优先等待后台只读复查或使用「核验转存」。已经核验到部分文件时，可以根据提示选择继续等待或“按已到的继续”；后者不会自动补下缺少的部分。

**115 显示 100% 或已完成，网盘也能看到文件，为什么仍待核验？** 下载进度和落地文件核验是两件事。Reelay 必须在本次任务的独占暂存目录（`.reelay-任务ID`）中，读到与清单名称、字节大小一致的全部文件；文件在其他目录、名称不同或列表尚未同步，都不能直接认定成功。旧版本还可能把已完成的下载误报为“还在下载，进度 100%”，掩盖文件不匹配的原因。核对暂存目录和转存清单后再核验；不要重复转存，也不要把“放弃”当成刷新按钮，它会删除本次暂存文件。

**一直是 0%，且 115 显示“等待中”怎么办？** 这表示 115 已接受任务但仍在等待下载，不等于 Reelay 没提交，也不能仅凭等待状态认定资源永久无源。“连续 3 次核验无变化”只是提前提醒，后台仍继续复查；「核验转存」不会重发云下载，也不会加速 115 的下载任务。

复查时机和停止条件见 [部署与运维](deployment.md#健康检查与故障恢复)。

### 20. 转存已经完成，整理失败了怎么办？

先看是不是片名/季集不对、同名冲突、目录权限或临时网盘问题。按照任务提供的按钮修正信息、处理冲突或重新整理。

“重新整理”使用已落地的文件，不需要重新转存。覆盖、删除本次文件或放弃任务可能影响网盘内容，先看清对象和提示。

### 21. 115 风控了，重启或重新登录有用吗？

风控和登录失效要分开处理：

- **登录失效**：在管理台重新扫码，后台会恢复。
- **操作频繁 / 风控冷却**：等待冷却结束。冷却状态会跨重启保留，频繁重试不一定有帮助。

出现大批积压时先检查来源数量、规则和自动处理范围，而不是不断提高并发。

### 22. 任务已入库，Jellyfin / Emby 为什么还看不到？

Reelay 只把文件整理到 115。媒体服务器如何读取网盘、如何挂载或建立媒体入口、什么时候扫描，都由你自己的播放方案负责。

先在 115 确认文件，再检查媒体服务器的读取路径和扫描状态。Reelay 的「媒体库」也是已入库任务汇总，不是对全部 115 文件的扫描结果。

## 费用、隐私与数据

### 23. Reelay 收费吗？消息会发送给谁？

Reelay 按 MIT 协议免费开源。机器、AI Token、网盘容量与云下载等第三方服务可能收费，以服务商规则为准。

启用 AI 后，相关消息和上下文会发给你配置的 AI 服务；TMDB 会接收作品查询，Telegram 与 115 各承担消息读取和网盘操作。自托管不意味着这些外部请求都留在本机。

“测试识别”“AI 生成规则”和部分只读查询也可能访问外部服务。不要用含私密信息的样例测试不信任的接口。

### 24. 备份配置文件就够了吗？重建容器会丢数据吗？

只备份 `config.yaml` 不够。订阅、入库记录、任务检查点、密钥、Telegram 会话和 115 凭证分别存放在数据目录里，应备份整个数据卷。

正常重建容器并保留同一数据卷不会等于清空数据；`docker compose down -v` 会删除卷，不能用作普通重启。

升级前停服务备份；数据库升级后要回滚，应同时恢复升级前的数据，而不是只换旧镜像。步骤见 [备份与迁移](deployment.md#备份与迁移)。

## 报告问题时需要什么

先查看 [GitHub Issues](https://github.com/Derrors/reelay/issues) 是否已有同类问题。新建反馈时建议附上：

- 使用版本、部署方式、机器架构。
- 问题发生在哪一步，预期是什么、实际是什么。
- 对应任务的状态、处理轨迹和错误时间。
- 相关来源规则、确认/放行方式；是否启用了订阅过滤。
- 必要时提供能复现问题的**脱敏样例**。

不要上传完整 `data/`、`secrets.json`、Telegram session、115 Cookie、Bot Token、AI 密钥或包含它们的请求日志。安全漏洞按 [安全政策](../SECURITY.md) 私下报告，不要把利用细节发到公开 Issue。
