# Reelay 文档

[在线文档站](https://derrors.github.io/reelay/) · [返回项目首页](../README.md)

Reelay 把你配置的 Telegram 来源消息，经过识别、审批或规则放行，转存到自己的 115 账号并整理成媒体库目录。**它是资源处理与整理工具，不是资源搜索引擎，也不是播放器。**

第一次使用不必读完所有配置字段。按你的目标，从下面一条路线开始。

## 先弄清这几个词

| 名称 | 简单理解 |
| --- | --- |
| 来源 | 你指定要监听的 Telegram Bot、频道或群组 |
| 个人账号 | 用来读取来源消息的 Telegram 账号，需要单独登录 |
| 控制 Bot | 你与 Reelay 交互的入口，接收卡片、发命令；不是监听账号 |
| Worker | 后台工作进程，执行监听、识别、转存和整理；只打开网页不能替代它 |
| 识别方式 | 用 AI 还是规则理解消息内容 |
| 确认 / 放行方式 | 根据规则决定自动转存、待审批还是忽略 |
| 订阅 | 要追的作品与季；本身不是“排除所有未订阅资源”的开关 |
| 仅处理订阅 | v1.5.0 起支持；把无法匹配有效订阅的资源直接忽略 |
| 保存目录别名 | Reelay 中的名称，映射到 115 的目标目录编号 |
| 已入库 | 文件转存、整理并完成核验，不是刚点了批准 |
| 待人工 | 流程需要你判断后才能继续，可能已有文件落地 |

## 版本与文档约定

- 文档随当前仓库源码更新，可能早于最新正式版，实际版本以 [Releases](https://github.com/Derrors/reelay/releases) 和 [更新日志](../CHANGELOG.md) 为准。
- 示例中的 `@example_channel`、示例片名和目录只是说明，请按自己的账号与网盘设置。快速开始中单独标注的推荐来源属于第三方。
- 指南中的「设置 → …」是管理台操作路径；代码块只有在你选择相应部署方式时才需要执行。
- 模拟运行与测试识别不等于真实转存。前者使用内置样例，后者可能查询外部服务但不创建转存任务。
